# db

## Init scripts

Run in alphabetical order by filename: 001 to 015. Schema only: a fresh volume has 0 rows in every table. Data comes from [Seed data](#seed-data).

- `001`: schema.
- `003`: uploads table and grants.
- `004`: document protection columns and shape CHECK (`db/init/004_document_protection.sql`).
- `005`: app role `sad_app` (uses `APP_DB_PASSWORD`; created by `005_app_role.sh` on fresh init only, since init scripts run only on an empty volume).
- `006`: RBAC tables, grants, and audit functions (`006_rbac.sql`).
- `007`: audit purge function `purge_audit_events` (`007_audit_purge.sql`).
- `008`: access levels and document grants (`008_access_levels.sql`).
- `009`: derive function `derive_document` and `derived_from` column (`009_derive.sql`).
- `010`: RED+STRICT and dual authorization (`010_red_strict_dual_auth.sql`).
- `011`: level change, raise by officer with commander approval, immediate lower (`011_level_change.sql`).
- `012`: unit head flag and at most one unit head per unit (`012_unit_head.sql`).
- `013`: login lockout, last sign-in, session idle tracking, login/logout audit vocabulary (`013_login_lockout.sql`).
- `014`: super admin flag `users.super_admin`; super admin takes either approval slot, never both (`014_super_admin.sql`). 014 must be applied before the backend that reads users.super_admin is deployed.
- `015`: field protection (`015_field_protection.sql`): `assets.ip_address` inet to text (tokens), CHECK limits widened to 4096 for ciphertext-sized reasons/names, `document_versions.sha256` dropped, request/level/Derive functions rewritten to store sealed text. Apply before deploying the backend that seals these fields.

`001` to `015` run automatically on a fresh (empty) `pgdata` volume. On an existing volume, apply `010` (`010_red_strict_dual_auth.sql`), then `011` (`011_level_change.sql`), then `012` (`012_unit_head.sql`), then `013`, `014` and `015` manually (see [access levels](../docs/access-levels.md#menerapkan-migrasi-010-dan-011-secara-manual)). See the root README, [Fresh start](../README.md#fresh-start); it deletes all DB data and old Vault volumes.

## Seed data

`seed/*.sql`, applied in filename order as the DB owner, before `seed-users.mjs`. Idempotent (`ON CONFLICT DO NOTHING`).

- `seed/001_reference.sql`: NIST CSF subcategories and ranks.
- `seed/002_seed.sql`: assets, documents, versions, links, initial audit (plaintext, `protection='none'`; generated by `scripts/seed-db.mjs`, do not edit by hand). Run the protect scripts afterwards.

```powershell
Get-ChildItem db\seed\*.sql | Sort-Object Name | ForEach-Object { Get-Content -Raw $_.FullName } | docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## Scripts

- `scripts/seed-users.mjs`: 80 demo accounts across 22 ranks, `access_level` per rank, DOC-0017 grants, and the derived demo child. Run first after fresh start. Needs `DEMO_USER_PASSWORD` (at least 16 characters). No `--dry-run`. Safe to re-run. Account list: [CREDENTIALS.md](CREDENTIALS.md).
- `scripts/tokenize-titles.mjs`: tokenizes plaintext titles and file names for non-CLEAR documents. Supports `--dry-run`. TPM crypto-api must be available. Dry-run and real runs exit 1 if any row fails.
- `scripts/protect-documents.mjs`: protection migration; seals every TLP (CLEAR included) and upgrades old `integrity` rows. Supports `--dry-run`.
- `scripts/protect-fields.mjs`: tokenizes `assets.ip_address` and `uploaded_files.name`; seals `assets.model`/`firmware`, non-CLEAR `document_versions.summary`, request/approval reasons and level-change free text. Supports `--dry-run`. Run as the DB owner (not `sad_app`). Idempotent: protected values are skipped. Needs `015` applied first.
- `scripts/seed-db.mjs`: regenerates `seed/002_seed.sql` from `frontend/src/test-utils/grc-fixture.ts` and the files in `seed-files/`.
- `seed-files/`: sample files read by `seed-db.mjs`. Not served by the app.

## Protecting documents

Seeded or new files are plaintext until protected. After [Fresh start](../README.md#fresh-start), run the dry run first:

```
docker compose run --rm --no-deps -v "./db/scripts/protect-documents.mjs:/app/protect-documents.mjs:ro" -e PGUSER=<POSTGRES_USER> -e PGDATABASE=<POSTGRES_DB> -e PGPASSWORD=<POSTGRES_PASSWORD> backend node /app/protect-documents.mjs --dry-run
```

Real run: same command without `--dry-run`.

- Every TLP, CLEAR included, is sealed via `/sealfile`. Old CLEAR `protection='integrity'` rows are upgraded to `encrypted` (existing HMAC tag reused if it verifies, else recomputed).
- Re-running is safe. Only `protection='none'` and `protection='integrity'` rows with a file are touched; versions without a file are counted as `no file` and skipped.
- Exit code is 1 if any row failed.
- Values in `<...>` come from the root `.env`. Never paste real values into docs or shell history.
- Limit: sealfile accepts up to 10 MiB decoded per file. Larger files stay `none` and are reported as failed.
- Caveat: if a document's TLP is changed later, re-running does not re-protect or un-protect existing versions. Out of scope; handle manually.

## Backup before migration

Before any protection migration, back up `document_versions` and `documents` with `pg_dump` (`-t document_versions -t documents`).

- Backup files contain plaintext.
- Keep them outside the repo, for example `%USERPROFILE%\secure-asset-doc-backups\`.
- Never commit them.
